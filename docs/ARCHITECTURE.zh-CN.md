# 系统架构 — 专为可组合性而设计

技能库与 MCP 适配器已在本仓库中实现。教育者可以直接使用本地技能文件，或将提示词复制到 AI 客户端中。下述的上下文引擎（Context Engine）与编排器（Orchestrator）属于架构提案，尚未在此实现为实际服务。[验证回执](audits/agent-skills-build-verification-2026-10-22.md)分别记录了本地检查结果与托管发布/客户端激活边界。

---

## 技能的结构设计

每个技能文件夹包含一个带有 YAML 头部和 Markdown 指南的 `SKILL.md`，以及可选的本地资源。规范源文件保留了扩展的教育元数据；生成的便携版本采用受限的标准前置元数据，并将完整元数据保存在 `references/education.json` 中。详见[格式与导出详情](AGENT_SKILLS.md)。

**YAML 头部**包含机器可读的元数据：技能 ID、领域、证据强度评级、带具名引用的证据来源、输入 schema（教育者提供的内容）、输出 schema（返回的结果）、串联元数据（哪些技能适合组合使用）、预计教师耗时以及发现标签。

**提示词（Prompt）**章节提供活跃工作流：角色设定、方法、输出要求与自检项。正文的其他章节则说明证据基础、局限性及可选资源。MCP 适配器仅提取活跃提示词；它不会自动提供整个文件或链接的示例。

这种双重结构意味着每个技能都可以：

- **由教育者直接阅读**：打开文件、复制提示词、填入输入字段，即可获得可用输出
- **由机器解析**：读取 YAML 头部以发现技能能力、校验输入、将输出路由至其他技能，并决定何时调用该技能

YAML schema 并非普通文档，而是接口定义。任何能够解析 YAML 的系统都能发现本库提供的能力、每个技能所需的输入以及它返回的输出。

## 三层系统架构

### 第 1 层 — 技能库（本仓库）

涵盖 20 个领域的 165 个技能。每个技能都编码了一项具体的、有研究依据的教学或课程设计决策——包括间隔复习排程、量规构建、支架式任务调整、自适应提示设计、面向学生的学习支持等。

教育者通过输入字段提供教学情境即可使用技能。Claude 会返回结构化且可直接使用的输出：间隔练习时间表、一组提取练习题、带有共建方案的量规，或针对特定语言熟练度调整的支架式任务。

使用复制的指令无需 Python 或 Node 构建。客户端安装与模型行为取决于所选集成方式；输出结果仍需教育者审阅。

### 第 2 层 — 上下文引擎（架构提案）

拟议中的上下文引擎位于技能库与编排器之间，用于保存持久化的班级与课程上下文。本仓库并未实现该存储层或其隐私与同意控制机制。

当通过上下文引擎调用技能时，输出将实现高度个性化。不再是关于间隔效应的泛泛建议——而是基于该班级上学期的学习内容、上次测评中哪些主题保持率较弱以及下次总结性评价时间节点所生成的专属间隔时间表。不再是通用量规——而是针对该发展阶段、该能力框架以及该学生当前表现水平校准的量规。

技能的输入 schema 已经为此做好了准备。每个技能都定义了 `optional`（可选）输入字段——学生档案、课程数据、评价历史、学校背景——专供上下文引擎注入。没有这些数据时，技能也能产出高质量输出；有了这些数据，技能便能产出量身定制的输出。

上述示例描述的是预期的未来行为，而非已实现的上下文引擎运行结果。

### 第 3 层 — 编排器（架构提案）

编排器允许教育者提出一个高层目标，即可获得一套完整、个性化的方案。

**示例：** 教育者说：*“为我的八年级班级设计一个为期 6 周的气候变化单元。”*

编排器将执行以下步骤：

1. 向上下文引擎查询班级档案、课程要求、先备学习情况与即将进行的评价
2. 调用**逆向设计单元规划器（Backwards Design Unit Planner）**，传入课程标准与持久性理解
3. 调用**间隔练习调度器（Spaced Practice Scheduler）**，在 6 周时间线上合理分配提取练习
4. 调用**交错练习单元规划器（Interleaving Unit Planner）**，重构主题顺序以增强相关概念之间的辨析度
5. 针对每节课，调用**课堂导入设计器（Lesson Opening Designer）**生成基于提取的导入活动
6. 针对班级中的 EAL 学生，调用**语言需求分析器（Language Demand Analyser）**
7. 为总结性评价调用**标准参照量规生成器（Criterion-Referenced Rubric Generator）**
8. 调用**生态探究锚点设计器（Ecological Inquiry Anchor Designer）**，将单元扎根于本地环境
9. 呈现一份完整的单元草案，供教育者审阅、编辑与批准

教育者自始至终处于决策环路中。编排器提出方案，教育者做出决策。这并非用 AI 取代教育者，而是让 AI 承担耗时的组装工作，使教育者能够专注于真正需要人类专业判断的决策——对这些学生而言什么最重要、什么需要优先、什么应当删减、什么需要调整。

每个技能 YAML 头部中的 `chains_well_with` 字段提供了显式的串联提示。编排器还可以通过匹配库中各技能的输出 schema 与输入 schema 来发现新的串联组合。

## MCP 服务器

MCP 服务器将完整的技能库暴露为提示词，并将允许模型调用的子集暴露为可调用工具。任何兼容 MCP 的客户端都可以发现全部 165 个提示词和 157 个工具、读取其输入要求，并使用严格的类型化输入。

由本库运营的公共端点随 v3.1.0 退役。本地 stdio 与自托管 HTTP 仍保持可用；详见[安装配置](../mcp-server/README.md)与[迁移指南](HOSTED_MCP_ACCESS.md)。

服务器将全部 165 个技能注册为提示词，并将其中 153 个技能注册为工具；标记为 `disable-model-invocation: true` 的 12 个技能仍可被发现并用于显式提示词调用，但不会作为模型自动调用工具暴露。另有四个元工具提供发现能力：`list_skills`、`find_skills`、`suggest_skills` 和 `get_skill_details`，共计 157 个工具。

自托管 HTTP 接口必须由其运营者主动部署和配置。保留的托管实现具备访问控制：要求配置规范的公共源站与高强度令牌/OAuth 密钥，仅在 `Authorization` 请求头中接受 Bearer 凭据，强制使用 S256 PKCE 与精确批准的重定向地址，并使用加密的短生命周期授权码与刷新凭据。新访问令牌在 30 天后过期；已部署的遗留签名/哈希/明文凭据仍保持兼容。SHA-256 吊销列表支持在不轮换签名密钥的情况下吊销单个凭据。

服务器在多实例间是无状态的。请求体大小受限（OAuth/访问申请请求上限为 16 KiB，MCP 请求上限为 1 MiB），而授权码/刷新令牌重放检测及访问申请防滥用限制则属于有界的内存级控制。它们能减少同实例内的重放与滥用，但在缺乏持久化共享状态的情况下，无法保证跨实例的严格单次使用。

源码与配置说明：[`mcp-server/`](../mcp-server/)

## Agent Skills 格式与发现机制

规范源文件保留在 `skills/<domain>/<skill-name>/SKILL.md`。插件入口为 `.claude-plugin/plugin.json` 和 `.codex-plugin/plugin.json`，各自列出领域目录。根目录下不存在 `plugin.json`。生成的 `dist/agent-skills/<skill-name>/` 版本属于严格便携视图；其[固定版本官方校验器 165/165 通过结果](audits/agent-skills-build-verification-2026-10-22.md)仅适用于该版本，而非扩展的源文件头部。

元数据优先发现与按需加载指令/资源是开放格式的渐进式披露设计。实际加载行为取决于客户端。12 个源文件标志请求“仅显式调用”；Codex 附属文件保留了该意图，且 MCP 将其排除在模型可调用工具之外。其他客户端可能会忽略这些策略；该标准并未强制规定全局统一的调用控制。

生成的 `registry.json` 支持发现/过滤，并提供无类型的 `chains_with` 建议。其 `chain_edges` 字段目前为占位符：`receives_from` 和 `feeds_into` 为空列表，`output_field` 和 `input_field` 为 null。注册表本身既不实现图执行，也不解决冲突。使用方编排器必须自行校验输入、解决相互竞争的建议并获取教育者审阅。

有关源文件/便携版契约、项目描述策略、版本含义及已测试的客户端限制，请参见[开发者指南](AGENT_SKILLS.md)。

## 贡献可编排的技能

添加到本库的技能应遵循 [CONTRIBUTING.md](../CONTRIBUTING.md) 中的 schema 规范。可编排就绪（Orchestration-ready）意味着：

- **YAML 头部完整** — 所有字段均已填充，输入和输出 schema 类型精确
- **输入和输出 schema 定义清晰** — 字段名称、类型与描述可供机器无歧义地解析
- **`chains_well_with` 已填充** — 在相关情况下列出能与该技能自然组合的技能 ID
- **`evidence_strength` 诚实标注** — 保留已记录的标签，并区分研究支撑与原创/实践者方法；请参阅[质量指南](SKILL_QUALITY.md)，切勿为了迎合打包格式变更而重新归类证据强度

Schema 是技能与任何调用它的系统之间的契约。此处的严谨性并非繁文缛节——而是实现可组合性的根本保障。
