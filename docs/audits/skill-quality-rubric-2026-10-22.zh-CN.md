# 教育技能质量量规与优化规则

2026-10-22。拟议评审量规，已应用于配套审阅中；并非新的纳入政策、实证认证或对项目规范的更改。基线 `main` 修订版本 `6bbbce418f82e11044009c9f3b7373a354de5bd0`。技能保持未动。

## 在此“卓越”意味着什么

一个卓越的教育技能能够为目标用户处理反复出现的教育任务提供可靠帮助，使重要决策显性化，妥善处理相关情境与局限性，并以相称的工作负荷产出用户可采取行动的成果。它提供具体的教育专业判断，同时不宣称拥有自身并不具备的权威性。当精简能够改善这种体验时是有益的；但它不能替代专业知识。

本库既有的 `CONTRIBUTING.md:21–36` 纳入要求与 `docs/EXCLUSIONS.md` 依然作为起始政策。本次审阅考察的是已被接纳的教育方法在多大程度上被良好地操作化，以便代理与用户使用。它不重新审理每项框架的入选资格，也不因实践者原创方法属于原创而将其视为有缺陷。原创框架需要诚实的范围界定与操作连贯性；针对某一部件的扎实证据不能验证整个组合干预的有效性。

开放标准提供了文件格式。其[编写指南](https://agentskills.io/skill-creation/best-practices)就范围连贯性、步骤与渐进式披露提供了有益建议。两者均不构成完整的教育质量评估。开展本项文本审阅无需先开展学习者成效研究或试点。反之，本审阅也无法确立临床安全性、模型遵循度、相对于不使用技能的边际收益或对学习者的实际有效性。

## 八项标准

| 标准 | 优秀表现的特征 | 修订的具体理由 | 需检查的证据 |
|---|---|---|---|
| C1 目的与选择 | 单一可识别的任务、目标用户、有用的触发器与范围；相邻技能之间具有可理解的差异 | 触发器实质性超出实际范围；将教师设计提示词误当作实时辅导；关于目标受众的误导性声明 | 描述、目的、必需输入、输出契约与明确排除项 |
| C2 增值专业度 | 具体的概念区分、决策规则、程序或防错知识，使任务更容易做好 | 泛泛的鼓励、无方法的任务复述、不起作用的术语、不必要的限制 | 实际的决策规则与推演逻辑；仅凭引用是不够的 |
| C3 可操作性与连贯性 | 输入导出可行的序列；分支彼此一致；必需数据/输出与示例遵循相同规则；完成状态清晰 | 相互矛盾的指令、不可达的分支、示例违反自身规则、生产方/消费方状态不一致、不存在的必需依赖 | 提示词与示例、输入/输出 schema、交接环节、默认值与停止条件 |
| C4 教育与证据完整性 | 教育主张准确且适度；来源身份可追溯；区分实证结果、理论与实践启发式规则 | 缺乏支撑的普遍性断言、不准确的来源主张、将重构措辞呈现为官方原文、已声明量表无法支撑的强评级 | 具名来源、精确主张、证据标签、局限性与输出标签；独立核查重大争议主张 |
| C5 情境敏感性与能动性 | 根据相关的学习者/任务证据进行调整；标明假设；保留必要支持；教师/学习者能够做出重大选择 | 硬性规则无视正确回答、准备度、调适需求或拒绝；从稀疏描述中推断诊断；将猜测的信心值当作有效数据 | 条件分支、可选上下文默认值、水平/语言可及性、用户覆盖与示例 |
| C6 实用性与工作负荷 | 输出可直接用于或编辑后用于所声明的任务；对建议排定优先级；使可行性与实施成本可见 | 过多的强制性产物、无后续行动、臆想的本地资源/合作伙伴、千篇一律的反馈、输出偏离目标构念 | 输出格式与示例；时间/资源、归属权、下一步行动与完成定义 |
| C7 边界与恢复机制 | 在需要处处理相关的不确定性、人类专业知识、隐私与安全保护；失败时具备可执行路径 | 将常规建议应用于紧迫危险；强迫披露/公开展示；编造缺失证据；在某一分发界面遗漏关键警示 | 核心指令、已知局限、危险边界案例、输入处理与 MCP 提取的提示词 |
| C8 精炼度与组织结构 | 核心规则易于查找；核心连贯且配有聚焦的可选参考资料；在防错处保留细节 | 重复的背景或角色声明、长示例始终被加载、隐晦规则埋没在长篇大论中、核心与示例不一致 | 完整激活内容对比核心提示词、章节大小、重复度、依赖与客户端交付 |

这些是用于有理有据评估的问题，而非八个等权重的数字评分。安全保护或事实准确性问题不能被精美的排版所平均抵消。包含许多有益示例的源文件并不自动违反 C8；它可能非常适合人类阅读，同时仅需要一个更轻量的代理入口。

## 锚定判断

针对每项标准，记录以下之一：

- **文本中有支撑（Supported in text）：** 具体段落证明了预期设计，且在既定审阅深度内未发现实质性相反证据。这不代表运行时通过。
- **存在疑虑（Concern）：** 存在可识别的矛盾、缺失的重大分支、误导性主张或强改进机会，且由路径与行号引用支撑。说明最小修正及其受影响界面。
- **尚未证实（Not established）：** 回答所需证据缺失，或该问题需要实际执行/外部验证。切勿用迎合性的高分或草率的失败判断来填补证据空白。

针对每个技能，选择一项主要操作：

- **保留（Keep）：** 在本次有界审阅中未发现有充分理由的内容变更。这不认证其完美无缺或具备实证有效性。
- **重组（Reorganize）：** 保留方法/内容；改善核心/参考资料分离或可发现性。基于长度的条目属于提示性建议，而非不合规失败或“更短输出更好”的证明。
- **修订（Revise）：** 存在有具体理由的针对性内容、工作流或边界修正。保留有用的其余部分，并在相关时将重组作为次要操作。

记录置信度与审阅深度。将具体的局部修订与共性机会（例如针对所有实时学习者记录的数据最小化）区分开来。切勿把一条共用的指令约定算作十三个独立证实的有害行为，从而人为夸大存在问题的技能数量。

## 在通用量规内应用不同的任务标准

| 任务类别 | 需保留与检查的特定质量特征 |
|---|---|
| 教案/单元设计 | 从学习目标到实际任务与证据的对齐；可行的时间表/资源；无装饰性活动或保证学习的虚假声明 |
| 评价与课程映射 | 评估预期构念；保留来源标识符/原始表述；区分覆盖度与深度/效度；呈现歧义与人类决策 |
| 学习科学设计 | 正确的先备知识/准备度条件；恰当的辅助、提取、反馈与撤架；区分一般证据与精确的时间表/阈值 |
| 实时学习者互动 | 有界的轮次、首次正确/无先备知识/拒绝回答的处理；适度的反思；诚实呈现不确定性与独立作答；用户控制权 |
| 包容性/福祉 | 保护现有支持与目标；避免诊断性推断或强迫披露；情境与即时安全边界；在需要处保留专家角色 |
| 历史/批判性探究 | 来源出处与不确定性；问题与史料适配度；区分事实核查与合理解读；不捏造引文或证据 |
| 原创/复合方法 | 声明实践者/综合状态；保留独特方法；组件与编排遵守实际契约；不暗示评分能验证该方法 |
| 教师专业学习 | 教师尊严/能动性；可实现的后续跟进；区分发展性反思与绩效诊断或考评 |

## 长度：做有理有据的编辑，而非凑配额

区分三种不同的计数：包含富元数据的完整文件、本地客户端交付的 Markdown 正文，以及 MCP 适配器实际提取返回的提示词。它们不可互换。一个文件可能看起来很长，但其活跃提示词已经很紧凑；反之，一个短提示词也可能规定不足或遗漏关键警示。

如有需要，可使用可重复的分词器代理指标，并明确命名。配套证据使用的是 `tiktoken 0.14.0` 的 `o200k_base`；这并非 Claude 分词器，也不代表任何已安装客户端的实际 token 消耗。标准中 500 行 / ~5,000 token 的建议是筛查指南，而非校验失败或经实验确立的最优值。

针对每个章节自问：

1. 这部分材料解决什么错误或决策？
2. 代理必须在行动前看到它，还是仅在特定分支中需要？
3. 同一规则是否已在别处陈述？重复是强化还是矛盾？
4. 它是代理执行所需、人类学习所需，还是两者皆需？
5. 移出它是否会破坏独立复制或 MCP 提取契约？

在核心中保留：预期用途、必需输入、决策序列、关键区分、强制性安全边界、停止/恢复规则以及精简的输出契约。仅在链接至明确加载条件时，才将冗长的完整示例、历史研究解释、替代模板与可选专家细节移出。绝不将关键局限性移出 MCP 唯一返回的文本之外。切勿为了统一体量而重写每个技能，也不要强迫一个极小核心去引用过多文件以致使用变得支离破碎。

## 实用的未来优化闭环

当前工作止步于审阅与提案。对于后续经授权的编辑：

1. 优先修复有来源支撑的矛盾、事实主张以及安全/能动性缺口。每次编辑均需附上修改前后理由以及“保留其余部分”的声明。
2. 有选择地重组最大的代理入口，保持研究/示例可访问。对比原始核心与提取后的 MCP 提示词，确保编辑改动不会移除所需行为。
3. 验证精确的不变量：稳定的 ID、必需输入、来源/引用保留、分支/示例一致性、真实链接、打包内容与现有校验。这些是检查项，而非新的研究计划。
4. 在实用性存在争议之处，检查具体的修改前后任务示例。仅在日后确有需要时，才针对冻结基线运行重复输出对比并辅以盲审专家评审。这是可选后续步骤，而非强加于当前任务的试点门槛。
5. 逐一接受/拒绝每个有界编辑，保留针对其所修复特定故障的测试用例。若日后引入自动对比评估，请保留一个独立的小型未见测试集。

若日后需要潜在的评估测试工具，它应当包含三份独立报告：确定性的打包/契约检查；对照本量规的专家内容审阅；以及任务输出对比。它必须标明实际运行了哪些检查。基于模型的评审器在信任其分数前需要经过人类校准；生成的模拟学生或对话脚本不能作为学习者收益的证据。此处未执行任何 API/模型评估运行、基准测试、微调或学习者实验。

## 版本与回滚

使用 Git 历史与带标签的已验收基线来保留原始版本；切勿使用 old/new/v2 名称复制活跃技能目录。对于兼容性改进，现有源路径/ID 保持稳定。拟议的核心/参考文件位于同一技能文件夹内并共同流转。保留被评估修订版本的完整证据以及每次获批编辑的理由。破坏性的输入/输出或教学法契约变更需要显式版本控制与文档化的过渡方案；真正不同的任务或许值得拆分为独立技能，但仅凭长度或编辑偏好不足以成为拆分身份的理由。

将失败的修订版本及其重新生成的注册表/打包产物一并回退。将安全/基础设施修复分开，以免内容回滚恢复不安全的解析。切勿仅因编辑审阅结果良好就自动提交或部署。除非后续明确指令授权进行有界替代，否则原始元数据/引用文献继续受仓库规范保护。
