# 教育技能质量标准

一个有用的技能能够帮助教育者或学习者以稳健的专业判断和适度的投入，完成一项反复出现的教育任务。文件格式校验使该技能具备可移植性，但并不能证明其教学方法的质量、模型的遵循度或学习成效。本库既有的[纳入标准](../CONTRIBUTING.md#inclusion-criteria)与[排除清单](EXCLUSIONS.md)依然适用，包括对实践者原创框架的诚实标注。

## 八项评审标准

请结合具体段落与示例，运用以下问题做出有理有据的判断。这些标准不是数字评分，也不是认证体系。

| 标准 | 审查要点 |
|---|---|
| 目的与选择（Purpose and selection） | 具备可识别的工作任务、目标用户与触发时机；清晰界定相邻技能之间以及面向教师与面向实时学习者之间的边界。 |
| 增值专业度（Added expertise） | 提供具体的概念区分、决策规则与防错机制，其价值超越泛泛建议或单纯的文献引用。 |
| 可操作性与连贯性（Actionability and coherence） | 输入、步骤、分支、示例与输出保持一致；交接环节切实可行且完成状态清晰。 |
| 教育与证据完整性（Educational and evidence integrity） | 来源可追溯且主张适度；明确区分研究发现、理论、实践启发式规则与原创综合。 |
| 情境敏感性与能动性（Context sensitivity and agency） | 回应准备度、无障碍需求、不确定性与用户选择；保留必要支持以及具有重大影响的人类决策权。 |
| 实用性与工作负荷（Practical usefulness and workload） | 输出可直接用于或编辑后用于所承诺的任务；后续行动、所需资源与负担切合实际。 |
| 边界与恢复机制（Boundaries and recovery） | 在需要处标明相关的不确定性、隐私、安全保护（safeguarding）与专家能力边界；当缺乏证据或路径不适用时提供可执行的恢复方案。 |
| 精炼度与组织结构（Economy and organization） | 核心规则易于查找；可选参考资料具有明确用途，且不会掩盖核心方法、例外情况或检查项。 |

请记录**文本中有支撑（supported in text）**、**存在疑虑（concern）**或**尚未证实（not established）**，并附上理由、证据与审阅深度。严重的准确性或安全保护问题无法被良好的排版格式所抵消。文本走查不能替代实际的模型测试。有关任务类别区分与示例，请参见[完整评审量规](audits/skill-quality-rubric-2026-10-22.md)。

## 证据与原创方法

基于研究的主张应引用可识别的文献来源，并如实呈现其实际发现与局限性。单一组件的证据不能证明完整组合工作流的有效性。[证据文献目录](EVIDENCE.md)为精选索引，并非对每一项主张的逐一验证。在现有纳入政策下，只要清晰说明其定位、独特方法与局限性，原创/实践者方法依然受到欢迎。

请诚实保留已记录的证据强度标签。现有元数据包含 `strong`、`moderate`、`emerging`、`original`、`practitioner` 以及历史遗留的 `low-moderate`/`medium` 值。保留这些标签并不代表进行了新的映射、重新定级或对底层证据进行了统一复核。对某项主张或评级的实质性修改都需要独立说明理由并核查来源。

## 变更审阅

对于实质性修订，请说明具体问题、最小修正范围以及需要保留的有用行为。通读受影响的整个技能及其资源。使用虚构或最小化信息检查常规案例与涉及的边界案例；检查实际交付的指令文本，若涉及则包括由 MCP 提取的提示词。对具有重大教育影响的变更，应获取独立的内容审阅。模型审阅可以挑战推理逻辑，但对于具有重大影响的安全保护或应对流程，不能替代合格专家的专业判断。

使用[贡献者命令](../CONTRIBUTING.md#validation-before-a-pull-request)分别检查结构、源文件/注册表/打包产物一致性以及便携版导出。这些检查不能认证课堂效益、法律合规性或实际客户端激活情况。当需要回答特定的行为问题时，可通过单独界定范围的模型/输出对比来验证；修正可识别的事实或工作流矛盾无需以开展实证试点为前置条件。

## 围绕任务组织内容

将适用范围、方法、必要边界、输出契约与自检项保留在活跃指令中。仅当主指南明确说明何时读取可选示例或扩展背景、且复制完整文件夹后依然可用时，才将其移至聚焦的本地参考文件中。完整保留内容并核验链接与示例；切勿为了凑字数配额而删减内容。

规范建议保持指令精简并采用渐进式披露，包括大致 5,000 个 token 和 500 行的参考上限。这些指导值并非“更短的技能效果更好”的证明，也不是通用的硬性失败阈值。请区分完整源文件、激活的 Markdown 正文以及提取出的 MCP 提示词：缩减其中一项可能使另一项保持不变。关键边界必须在每个交付界面中得以保留；托管 MCP 不会自动加载链接的示例文件。

## 连续性与回滚

在原位改进现有的稳定技能路径与 ID。Git 历史、基线哈希与审阅回执负责保留早期版本；切勿为了留存历史而复制出多个活跃的 `v1`/`v2` 目录。对教育学含义的修改需要明确的理由与保留性检查。若需回滚，请将受影响的源文件与资源连同重新生成的注册表、MCP 快照及便携版视图一并恢复，同时保留无关的已验收工作与安全修复。

[10 月 22 日构建回执](audits/agent-skills-build-verification-2026-10-22.md)、[165 行处置台账](audits/agent-skills-build-dispositions-2026-10-22.csv)与[质量变更日志](audits/skill-quality-change-log.md)明确区分了已实施的修订与早期提案。全部 165 个技能均经过筛查，但并非所有研究主张都接受了同等深度的一手文献核查。源文件审阅与虚构走查不能确立实证效能；更广泛的研究核验、关键场景下的专家审阅以及客户端/模型评估仍是界定清晰的未来工作。
